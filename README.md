# Pharmacy-Tutor

**面向药学教师的 AI 备课与复习支架系统** —— 以"先生理、后药理"纵向整合为教学契约，基于教材证据检索的生成管线，辅助教师完成药理学课程材料的起草与复习。

> **An AI-assisted lesson-preparation and review scaffold for pharmacology educators.** Pharmacy-Tutor generates physiology-first, vertically integrated teaching materials grounded in a textbook evidence-retrieval pipeline, under explicit teacher supervision. It is a teaching scaffold — **not a clinical decision-support system**.

## 项目定位

- **使用对象**：药理学课程教师（备课、习题、病例、复习材料起草）。
- **设计原则**：生理机制先行、药理应用在后；每条生成内容附带可核对的教材来源片段。
- **边界声明**：本系统是教师监督下的备课/复习支架，不是临床决策系统，不用于患者个体化诊疗。

## 核心能力

| 能力 | 说明 |
|---|---|
| 四种教师技能模式 | 智能问答、题目生成（含答案与解析）、病例教学、备课提纲 |
| 三段式教学契约 | 回答按「生理基础、教材要点、补充说明」组织，生理–药理机制要求锚定生理环节 |
| 来源卡片 | 检索片段附卡片展示供教师溯源核对；检索覆盖档案随记录导出 |
| 无证据兜底 | 检索为空时直接返回约定的无证据回答，不调用模型、不硬答 |
| 语言跟随 | 回答语言按输入判定（中英启发式），界面语言切换不强制翻译 |
| 会话与安全 | 账号登录门控（HttpOnly Cookie）、速率限制、会话持久化、SSE 流式响应 |

## 检索设计取向

采用朴素 RAG 取向：教材**原文片段**不经抽取、摘要或结构化改写地提供给模型与教师复核。管线为关键词 + 向量双通道深候选 → 混合分重排 → 实体锚点覆盖过滤 → 按书源多样化 → 同小节邻块前后向扩展 → 生理车道补充依赖路径。中文药名对英文语料的召回缺口由 2,023 条中→英术语别名与双向术语表扩展弥补。

## 知识库

七个教材来源：药理学（第9版）、临床药理学（第6版）、Katzung《Basic and Clinical Pharmacology》（第14版）、Goodman & Gilman（第12版）、学习指导与习题集（第4版，仅习题）、DrugBank 药物专论库（3,774 条）、MSD Manual 专业版主题（2,782 个）。2026-10-27 重建后 ChromaDB 集合含 93,400 个向量块，嵌入模型 `text-embedding-3-large`（3072 维）。习题集与 MSD 经 OCR/格式转换管线处理，OCR 误差需对照原书核验。**RAG 语料属教研室内部材料，不对外分发。**

## 技术栈

- **后端**：Python / FastAPI，检索问答、流式响应、访问门控、限速
- **前端**：React / Vite
- **检索**：LangChain 关键词检索 + Chroma 向量检索，混合重排与实体锚点过滤
- **部署**：Docker 多阶段构建；曾以 Cloudflare 隧道 + systemd 方式提供在线实例
- **模型接入**：OpenAI 兼容接口（生成 + 嵌入）

## 证据边界（重要）

- 检索片段是提供给模型的上下文，**不是逐条论断的引用核验**；命中片段仍可能不相关或不充分。
- 生理系统查询规则为关键词匹配的教学线索，覆盖不完整，可能漏检或召回不贴切片段。
- 教材经 OCR 入库，药名、剂量、公式、否定词与习题答案可能识别有误，需核对原书；无定量 OCR 错误率估计。
- 三段式结构是生成要求，**不保证模型逐次遵守**；检索为空时后端直接返回约定的无证据回答。
- 教学有效性、生理准确性、因果衔接与跨模型泛化**均未在本项目中建立**。
